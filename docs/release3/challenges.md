## Modularization of the project
The first biggest challenge we faced during the project was modularization of the project. The difficulties arose from our limited experience with modularization and an initial misunderstanding of the requirements for each module. This disrupted our workflow and time management, as we prioritized completing other updates first to minimize potential merge conflicts, and each optimization took longer than expected, delaying the modularization process. Another complication with modalrization was arranging the dependencies correctly. At first, we attempted to make every module dependent on all others, which created circular dependencies and build errors. With guidance from another group, we developed a cleaner and more effective structure. In the solution, all modules depend on the model module. The persistence module depends only on model, while the core module depends on both persistence and model. Finally, the ui module depends on all three: model, persistence, and core. This hierarchy avoids circular dependencies, ensures no module depends on itself or sibling modules, and establishes a clear parent-based structure. Looking back, we realize that if we had planned modularization and dependencies from the very start of the project, we could have avoided extensive changes and reduced the risk of conflicts. In future projects, we would prioritize defining the module structure early, carefully planning dependencies, and consulting experienced sources when necessary. This approach ensures smoother development, easier maintenance, and a more organized workflow throughout the project.
