## Workflow for release 3

Throughout the period of the project we have had weekly meetings where we update each other on what we have been working on. The meetings are usually more productive for us, as we are contributing a lot more and can help each other with the code. For the 3rd release, we've had more frequently meetings, and worked a lot more intense on the project. We've been setting up a lot of issues on our project board, and assigning them consistently. The issue board helps us know exactly what everyone is working on and that prevents us from getting any unnecessary conflicts that would steal time from us. One thing that came up close to the submission deadline, was that we noticed one of our group members had logged in with his personal account on VS code, and the NTNU account on GitHub. That means all commits through VS Code or the terminal were being linked to his private account, and the merges on GitHub were being linked to the NTNU account. The fix for this was that he went through the whole Git log and searched for instances of his username and mail, and then replaced them with his NTNU information. However, this created another issue. A whole new commit history were created and that meant anyone who had made a branch in the old history received some problems when they were trying to create a pull request to merge their branch into main. Then we had to find a fix for this, which included just creating a new branch on the new commit history, and then rebase the old branch. This allowed us to merge correctly into main again.

Although we had some problems in our workflow throughout the project, we have worked together to find good solutions to fix them. We've had a good workflow and worked well together, and that has helped us create and maintain a good group work ethic.
