## Workflow

We start of every workflow cycle with a meeting where we discuss what needs to be completed before the next assignment. We then create issues for what needs to be done and assign the ones we’ll work on first, changing their status from “Todo” to “In progress”. When development begins, we write the necessary code and, when we believe it’s done, create pull request. One of the team members who was not involved in writing the code s then asked to give a review. We also move the issue to “in review” on the issue board. If the reviewer finds any issues and suggests improvements, they will provide the necessary feedback so that the author can make improvements and request another review. Finally, when the code meets the expected criteria, the reviewer approves it for merging with our main branch. The branch is then deleted, and the issue is moved to “Done” on the issue board.
